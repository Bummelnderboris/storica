# Legacy — the v1 web app

Nothing in this folder runs, and nothing outside it imports from here. It is kept because it is
the evidence behind the v2 design, not because it is a fallback.

## What this was

Storica v1: a FastAPI + React web application. A user filled out a "Story DNA" quiz in the browser,
picked an author *House*, and an 8-phase agent pipeline wrote a novel while progress streamed back
over a WebSocket, pausing for approval between planning phases.

```
legacy/
  backend/
    app/
      core/          hexagonal domain: entities, ports, use cases
      adapters/      Anthropic LLM, SQLAlchemy storage, WebSocket events, YAML authors
      agents/        the 8 phases — phase0_author .. phase7_consistency
                     phase6_prose/ is the reason→write→critique→revise loop
      api/           FastAPI routers: auth, projects, authors, pipeline, websocket
      models/        SQLAlchemy ORM
      prompts/       the v1 prompt templates — the ones novels/der-chrachen was captured with
      orchestrator/  an alternative orchestrator, never wired to the live path
      tasks/         a Celery task queue, never invoked from the API
      services/llm.py  a duplicate of the Anthropic adapter
      authors/profiles/  v1 author YAML — superseded by /authors/<id>/
    alembic/         migrations 001–003
    authors_yaml/    austen / hemingway / king — referenced by nothing, even in v1
  frontend/          React 18 + TypeScript + Vite + Tailwind + Zustand
  docker-compose.yml postgres + redis + backend + frontend
  .env.example       the Gemini-era config, from before the switch to Claude
  story_output/      two early novels generated by the v1 pipeline
```

The last four entries under `backend/app/` were already dead *inside v1* — leftovers from two
earlier design directions (a Celery-driven queue and an alternate orchestrator).

## Why it was superseded

v1 was not abandoned for being broken. It ran, and its prose was good sentence by sentence. It was
abandoned for a structural reason found by reading a complete captured run
([`novels/der-chrachen/FINDINGS.md`](../novels/der-chrachen/FINDINGS.md)):

**every stage passed prose forward, and the next stage re-interpreted it.** Prose is lossy, so
meaning leaked at every hand-off. The story bible was seeded from prose rather than ground truth,
so a single early slip — the writer recast a priest as a creditor — was recorded as canon, threaded
into later chapters, and then *elaborated* by agents trying to reconcile it. The revision loop, told
to "make it consistent" without the original character sheet, made it strictly worse: it renamed the
victim and changed the cause of death from a fall to poisoning, breaking the plot, while scoring
*higher* because the surface complaints were gone.

No amount of tuning fixes that, because the state substrate itself is the problem. v2 replaces it:
canon is structured and versioned, prose is only ever an output, and conflicts resolve to frozen
ground truth instead of to a mutable bible. See [`/DESIGN.md`](../DESIGN.md).
